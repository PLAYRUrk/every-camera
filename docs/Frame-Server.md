# HTTP-сервер кадров

На каждой машине с камерой работает небольшой HTTP-сервер (`frame_server.py`). Он запускается вместе с измерениями в консольном режиме и в GUI.

Сервер не мешает измерениям:

- работает в отдельных daemon-потоках; если порт занят или значение в секции `server` некорректно, выводится предупреждение, сервер не запускается, а измерения продолжаются;
- обработчики не обращаются к камере: живые кадры берутся из потокобезопасной прослойки, архив читается с диска;
- ограничены число одновременных видеопотоков и размер листинга;
- имя файла проверяется на выход за пределы архива;
- тело POST-запроса больше 1 МБ получает HTTP 413;
- на Windows порт занимается эксклюзивно, поэтому две камеры не могут делить один порт.

> **Доступ из локальной сети не защищён паролем.** Любой в локальной сети может смотреть кадры и менять параметры съёмки, если камера это поддерживает. Используйте сервер только в доверенной сети. Чтобы закрыть доступ, поставьте `"bind": "127.0.0.1"` или `"enabled": false`.
>
> Извне сервер доступен через [туннель Cloudflare](Tunnel.md): там без токена разрешено только чтение.

## Параметры

Секция `server` в `config.json`:

| Ключ | По умолчанию | Описание |
|---|---|---|
| `enabled` | `true` | включить сервер |
| `bind` | `0.0.0.0` | адрес прослушивания; `127.0.0.1` — только эта машина |
| `port` | `8765` | предпочтительный порт |
| `port_search` | `20` | сколько портов выше `port` перебрать; `0` — только `port`. См. [Несколько экземпляров](Multi-Instance.md#порт-lan-сервера) |
| `discovery` | `true` | отвечать на поиск камер |
| `discovery_port` | `45455` | порт обнаружения |
| `max_list` | `5000` | наибольшее число кадров в ответе на листинг; viewer_app просит столько же |
| `focus_ttl` | `60` | сколько секунд камера остаётся в режиме фокусировки после последнего запроса |
| `tunnel` | см. [Доступ извне](Tunnel.md#параметры) | туннель Cloudflare и рассылка его адреса |

## Точки доступа

| Запрос | Назначение |
|---|---|
| `GET /` | встроенная веб-страница для просмотра кадров из браузера |
| `GET /api/info` | имя экземпляра, тип камеры, возможности, расписание |
| `GET /api/status` | текущий статус воркера |
| `GET /api/dates` | даты, за которые есть кадры |
| `GET /api/frames?date=&limit=&offset=` | листинг архива |
| `GET /api/frame?name=&as=jpeg\|raw&max=&stretch=` | кадр: JPEG для показа или оригинал |
| `GET /api/thumb?name=` | миниатюра |
| `GET /api/stats?name=` | статистика и гистограмма; без `name` — живого кадра |
| `GET /api/composite?first=&previous=&last=&window=&stretch=&max=` | разностный кадр из трёх кадров (Japan) |
| `GET /api/latest.jpg` | последний живой кадр; то же `/api/latest` |
| `GET /api/live.mjpg?fps=&max=` | MJPEG-поток; то же `/api/live` |
| `GET /api/params` | текущие параметры и схема редактируемых полей |
| `POST /api/params` | запрос на изменение параметров |
| `GET /api/params/<id>` | результат запроса на изменение |
| `POST /api/focus` | включить, продлить или выключить режим фокусировки |
| `GET /api/nodes` | все камеры, о которых знает эта, включая её саму |
| `GET`, `POST /api/node/<host>:<port>/<путь>` | тот же запрос к соседней камере: см. [шлюз](Discovery-And-Gateway.md#шлюз) |

## Просмотр архива без камеры

Сервер можно запустить отдельно над каталогом с кадрами, например на машине, куда снимки скопированы:

```bash
python -m frame_server --output-dir /path/to/output --port 8765 --node-name "Архив"
```

Чтобы архив раскладывался по циклам, серверу нужно расписание из конфига:

```bash
python -m frame_server --output-dir /path/to/output --camera-type japan \
                       --config config.json
```

| Параметр | Назначение |
|---|---|
| `--output-dir` | каталог архива, плоский или дерево `ГГГГ/ММ/ДД`; обязателен |
| `--port` | порт, по умолчанию `8765` |
| `--bind` | адрес, по умолчанию `0.0.0.0` |
| `--name` | имя экземпляра, по умолчанию `archive` |
| `--node-name` | имя в списке при сканировании сети; по умолчанию имя хоста |
| `--camera-type` | тип камеры, по умолчанию `unknown` |
| `--config` | конфиг, из которого берётся расписание |
| `--no-discovery` | не отвечать на обнаружение |
| `-v`, `--verbose` | подробный вывод |

К такому серверу подключается `viewer_app.py` или браузер.
