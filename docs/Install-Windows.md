# Windows

На Windows работает машина наблюдателя и станция с камерой Japan целиком: расписание, тёмные кадры, управление интенсивностью, запись FITS, консоль, статусы для монитора, LAN-сервер, живой просмотр, оповещения и сторож.

## Что поддерживается

| Компонент | Windows |
|---|---|
| `viewer_app.py`, `focus_app.py`, `monitor_app.py`, обнаружение, шлюз | да |
| Камера Japan (Hamamatsu DCAM-API и колесо фильтров) | да, целиком |
| `setup_app.py`, `gui_app.py` | да |
| `alerts.py`, `mailer.py`, `sentinel.py` | да |
| Камера ASI | нет: в `cameras/asi/picam.py` нет кандидата `Picam.dll` |
| Камера Canon | нет: нужны `gphoto2`, `gio`, `pkill`, `fuser` |
| Камера Infra | нет: нужны `libTanhoAPI.so` и `libusb-1.0.so.0` |
| `run.sh`, systemd | нет, вместо них `run.cmd` и «Планировщик заданий» |

## Что установить

- Python 3.11 и `pip install -r requirements-japan.txt`.
- DCAM-API SDK. Установщик кладёт `dcamapi.dll` в `System32`, и настраивать ничего не надо. Если библиотека лежит в другом месте, укажите файл через `DCAM_LIB` в `env.cmd`. Обёртки Hamamatsu уже лежат в `cameras/japan/dcamsdk/vendor/`.
- Драйвер USB-переходника колеса фильтров: FTDI, Prolific или CP210x, смотря какой в переходнике.

Прав на USB раздавать не нужно.

## Запуск

`run.cmd` принимает те же аргументы, что и `run.sh`:

```bat
run.cmd --type japan
run.cmd --gui
run.cmd --sentinel
```

Скрипт переходит в каталог программы и вызывает `env.cmd`, если он есть. Интерпретатор выбирается в таком порядке: `%PYTHON%`, `venv\Scripts\python.exe` рядом с программой, `python` из `PATH`.

Машинные настройки (`DCAM_LIB`, активация conda) кладите в `env.cmd`. Образец — `env.cmd.example`, сам `env.cmd` находится в `.gitignore`.

Автозапуск делается через «Планировщик заданий»: триггер «При запуске компьютера», действие `run.cmd --type japan`.

## Остановка

Останавливайте камеру **Ctrl+C**, а не крестиком окна.

Ctrl+C и Ctrl+Break доходят до драйвера как обычно: он дописывает текущий кадр, снимает финальные тёмные и закрывает затвор. Закрытие окна консоли, выход из системы и выключение машины драйвер тоже видит через `SetConsoleCtrlHandler`, но Windows даёт на завершение лишь несколько секунд. Длинная серия финальных тёмных может не успеть.

## Отличия от Linux

- **COM-порт вместо `/dev/ttyUSB0`.** Мастер настройки и новый `config.json` сами предлагают `COM3`. Номер порта смотрите в «Диспетчере устройств» → «Порты (COM и LPT)». После перестановки в другое гнездо он может измениться. Устаревший порт открывается молча и не отвечает, и ночь уйдёт в архив без меток фильтров. Стабильных имён вроде `/dev/serial/by-id/...` на Windows нет, поэтому проверяйте номер после каждой перекоммутации.
- **Нет средней загрузки процессора.** В мониторе не будет строки `load_avg`. Память и свободное место на диске показываются как обычно.
- **Каталог конфигов служб.** Сторож ищет их в `%PROGRAMDATA%\every-camera` вместо `/etc/every-camera`. Если их там нет, он берёт `config.json` из каталога программы. Так станция на Windows обычно и настраивается.
- **Резервирование имени экземпляра** работает через `msvcrt`, поэтому две копии программы на одной машине получают разные имена. См. [Несколько экземпляров](Multi-Instance.md).
