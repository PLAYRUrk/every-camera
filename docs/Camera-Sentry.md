# Камера Sentry

Камера Princeton Instruments CCD под управлением стороннего демона `imagerd_rt` (Keo Scientific, бинарный файл). Драйвер работает **супервизором**: генерирует `schedule.conf`, запускает демон, читает его файлы и публикует статус и кадры в локальную сеть.

```bash
python main.py --type sentry
```

## Подключение

`imagerd_rt` обращается к камере напрямую через SDK (Picam и Pleora eBUS). Права настраиваются по документации Keo Scientific и Princeton Instruments для конкретной модели. Every-camera запускает `imagerd_rt_start` как пользовательский процесс, поэтому достаточно прав на исполнение бинарного файла.

На Windows камера не поддерживается.

## Параметры

| Ключ | По умолчанию | Описание |
|---|---|---|
| `instance_name` | `""` | имя экземпляра; пусто — `Sentry_<узел>` |
| `imagerd_rt_dir` | `/usr/local/imagerd_rt` | каталог установки демона |
| `output_dir` | `""` | каталог архива FITS (необязательно) |
| `device_id` | `ASI1` | идентификатор устройства |
| `site_id` | `SITE` | идентификатор станции; сохраняется, но программа сейчас его не использует (в именах файлов его нет) |
| `zenith_angle_start` | `-10` | угол Солнца начала измерений, градусы; отрицательный — Солнце под горизонтом |
| `schedule_len_ms` | `1440000` | длина цикла, мс (24 минуты) |
| `imaging_mode` | `schedule` | `schedule` — по слотам, `rapid` — непрерывная съёмка |
| `capture_seconds` | `[0, 30]` | секунды каждой минуты для опроса статуса демона |
| `slots` | `[]` | слоты расписания |

## Слоты

Каждый слот описывает один сеанс съёмки со своим светофильтром внутри цикла.

| Поле | Описание |
|---|---|
| `filter_num` | номер светофильтра |
| `start_ms` | начало слота от начала цикла, мс |
| `exposure_ms` | экспозиция, мс |
| `binning` | биннинг: `1`, `2` или `4` |
| `gain` | усиление ПЗС: 1–3 для ProEM, зависит от модели |
| `readout_ms` | перемещение колеса и считывание матрицы, мс |

Пример — два фильтра каждые 24 секунды:

```json
"slots": [
  { "filter_num": 1, "start_ms": 0,     "exposure_ms": 8000, "binning": 2, "gain": 3, "readout_ms": 3000 },
  { "filter_num": 2, "start_ms": 12000, "exposure_ms": 8000, "binning": 2, "gain": 3, "readout_ms": 3000 }
]
```

Из слотов драйвер генерирует `schedule.conf` при каждом запуске.

## Файловый интерфейс imagerd_rt

| Файл | Описание |
|---|---|
| `<dir>/schedule.conf` | расписание, генерируется драйвером |
| `<dir>/aux/image.fits` | последний кадр |
| `<dir>/aux/meta-data.txt` | метаданные кадра: пары ключ-значение через TAB |
| `<dir>/aux/seqno.txt` | счётчик кадров |
| `<dir>/aux/stop_file` | управление: `10` — стоп, `11` — возобновить |

## Ограничения

- Расписанием владеет демон, поэтому `focus_app.py` не может его приостановить. Живой поток работает, а изменяемых параметров нет: см. [Настройка резкости](Focus.md). Кадры, показанные в `focus_app.py`, всё равно архивируются на :00/:30.
- FITS пишет сам демон. Статистика в `viewer_app.py` приводится к общей [шкале интенсивности](Intensity-Scale.md).
- При остановке драйвер записывает `10` в `stop_file`, демон завершает цикл и останавливается.
