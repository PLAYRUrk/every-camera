# Настройка резкости

`focus_app.py` даёт живой поток кадров, изменяемые параметры съёмки и числовую оценку резкости.

```bash
python focus_app.py                      # найти камеры в локальной сети
python focus_app.py --host 192.168.1.5   # сразу подключиться
python focus_app.py --host 192.168.1.5 --port 8766
python focus_app.py --host 10.0.0.5 --via 192.168.1.5:8765   # через шлюз
```

## Порядок работы

1. **Search LAN** → выбрать камеру → **Start live view**.
2. Крутить фокусер, следя за числом резкости и графиком. При точной фокусировке значение достигает максимума (`100 % of best`), а зелёная пунктирная линия показывает лучший результат за сеанс.
3. Навести [измерительный квадрат](#измерительный-квадрат) на нужную звезду.
4. Изменить значения на панели **Camera parameters** → **Apply**.
5. **Stop** возвращает камеру в обычный режим.

Строка под графиком показывает `⚠ overexposed`, если насыщено больше 1 % пикселей.

## Что происходит с измерениями

Подключение `focus_app` **приостанавливает расписание**, камера отдаёт кадры без ограничений.

- Если камера ведёт измерения, программа спрашивает подтверждение: «Pause and focus» или «Leave it measuring». Пропущенные слоты не доснимаются.
- В режиме настройки и вне окна наблюдений предупреждения нет: прерывать нечего.
- **Stop**, закрытие окна или потеря связи возвращают камеру к расписанию. При обрыве связи удержание снимается по тайм-ауту, не дольше 10 минут. Расписание продолжается со следующего подходящего слота.
- Начатая экспозиция никогда не прерывается.
- Исключение — **Sentry**: расписанием владеет `imagerd_rt`. Живой поток работает, а `focus_app` сообщает об этом в строке статуса.

Пока удержание действует, на панели Connection горит `measurements paused for focusing`, а в мониторе плитка пишет «Measurements paused while someone focuses this camera».

### Защита измерений

- Плановая съёмка всегда в приоритете: рядом с секундами `capture_seconds` кадры фокуса не берутся.
- Камера снимает свободно, только пока `focus_app.py` подтверждает, что за ней смотрят. Срок задаёт `server.focus_ttl`, по умолчанию 60 с.
- После пяти ошибок подряд при съёмке кадров фокуса режим выключается; MJPEG-поток его не оживляет.
- MJPEG-поток не удерживает сеанс фокуса (и удержание расписания) после того, как зритель отключился.

## Измерительный квадрат

Слева показан весь кадр, справа — содержимое квадрата на всю ширину панели. Резкость считается только по квадрату.

| Управление | Действие |
|---|---|
| клик или перетаскивание по кадру | навести квадрат |
| **Ctrl + колесо** | изменить сторону |
| **Side** | сторона в пикселях; `0` («whole frame») — весь кадр |
| **Centre X / Y** | координаты центра в пикселях |
| **Centre** | вернуть квадрат в середину |
| **Zoom main view too** | показать квадрат и в левом виде |
| **Smooth the square preview** | сглаживание фрагмента; по умолчанию выключено, потому что дорисовывает границы, по которым идёт оценка |

Центр хранится в долях кадра, поэтому наведение не сбивается при смене **Max size**. Квадрат у края сдвигается внутрь, а не обрезается. Смена размера или положения сбрасывает график.

## Параметры камер

Панель строится по ответу камеры.

| Камера | Живой поток | Изменяемые параметры |
|---|---|---|
| Canon | Live View (`get_preview`), при отказе — обычный снимок полной выдержки, только если он закончится не позже чем за 5 с до ближайшей секунды съёмки | `iso`, `shutterspeed`, `aperture`, `whitebalance` |
| SPTT | непрерывный захват между плановыми снимками | `exposure`, `gain`, `binning`, `encoding` |
| Infra | поток кадров камеры | `exposure_us`, `gain`, `roi` (при смене ROI экспозиция сохраняется) |
| Sentry | кадры `imagerd_rt` по мере появления | нет |
| ASI | кадр в паузе между плановыми, если успевает до слота | `exposure`, `binning`, `gain`, `filter`, `shutter`, `target_temp` |
| Japan | то же, что у ASI | `exposure`, `binning`, `readout_speed`, `filter`, `shutter` |

### ASI и Japan

- Живой кадр берётся, только когда до планового снимка остаётся больше экспозиции с запасом.
- Параметры применяются между экспозициями. Параметр, изменённый из `focus_app` во время ожидания планового слота, в этот слот не попадает: перед экспозицией заново применяются собственные настройки слота (фильтр, экспозиция, биннинг, усиление). Слот без своего `gain` использует `asi.camera.gain`, а не то, что оставил фокус.
- Камера отзывается в любом состоянии: каждое ожидание драйвера, включая ожидание Enter, обслуживает живые кадры.
- Затвор открывается для сеанса сам и закрывается, когда сеанс кончается или начинаются измерения. Если оператор выставил затвор вручную, по окончании сеанса он возвращается в прежнее состояние (открывается заново только на время измерения).
- Живой кадр могут не дать плотное расписание и съёмка тёмных кадров. Причину показывает поле `focus_note` в `/api/status`, она видна и в `focus_app`.

**Затвор.** Им управляет контроллер колеса. Измерительная программа держит его закрытым до конца стартовых тёмных кадров, поэтому в форме есть флажок **Shutter — open**. Состояние видно в консоли, строка `Shutter:`. Закрытие затвора при работающем расписании сопровождается предупреждением. Значение принимается и словом: `open`, `closed`.

**Положение колеса.** `home` (0) — известное положение после запуска, `unknown` — несостоявшийся поворот: не сработали опрос контроллера, повтор и пересоздание связи. В именах файлов и FITS оба записываются как `0`. Успешный поворот пишется в лог со временем хода (`Filter 3 reached in 1.1 s`), и по ней видно, растёт ли время.

В форме `home` показывается серым, выбрать его нельзя. Выбираются только фильтры `1..6`. Когда положение неизвестно, поле пустое. В схеме параметров такие значения лежат в `states`, а не в `choices`.

### Infra

Кадр, на который пришлась смена параметра, пропускается. При смене ROI камера сбрасывает экспозицию, поэтому драйвер возвращает прежнюю. Вкладка Infra в GUI принимает `roi` из `focus_app`, а кнопки Set exposure/gain/ROI во время измерения отказывают.

### SPTT

Период кадра в форме отсутствует намеренно: он [следует за экспозицией](Camera-SPTT.md#экспозиция-и-период-кадра). Первый кадр после смены параметров отбрасывается.

## Значения в форме

Камера меняет настройки сама: расписание переключает фильтр и выдержку, затвор ASI открывается после тёмных кадров. Поэтому драйвер публикует текущие значения с частотой статуса, а `focus_app.py` перечитывает `GET /api/params` раз в несколько секунд.

- Поле, которое оператор изменил и не отправил, сохраняет введённое значение и помечается звёздочкой (`Shutter *`). Во всплывающей подсказке написано, что сообщает камера.
- Пометка гаснет, когда камера сообщит применённое значение, а также по кнопке **Reset fields**.
- **Apply** отправляет только то, что оператор действительно менял.
