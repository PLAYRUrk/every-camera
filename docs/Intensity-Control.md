# Управление интенсивностью

Две необязательные функции, обе по умолчанию выключены. Ключи, значения по умолчанию и логика у всех камер общие: арифметика в `cameras/common/exposure.py`, состояние и сообщения в `cameras/common/intensity_control.py`.

| Функция | Секция | ASI | Japan | SPTT | Infra | Canon |
|---|---|---|---|---|---|---|
| Предварительная стадия с авто-экспозицией | `preflight` | `sun_cycle` | `sun_cycle` | `mode: "sun"` | нет | нет |
| Защита от пересветки | `overexposure` | `time`, `sun_cycle` | только `sun_cycle` | всегда | всегда | нет |

Включённая в режиме `time` защита у Japan сообщается при запуске и выключается: этот режим сохраняет программу `japan-camera`, один кадр на слот. Причина описана в разделе [Общее у ASI и Japan](ASI-Japan-Shared.md#почему-разбиение-слота-у-japan-только-в-sun_cycle).

У Infra нет предварительной стадии: эта камера снимает по файлу интервалов и не знает высоты Солнца. Canon в управлении интенсивностью не участвует: кадр — JPEG с нелинейной яркостью, а выдержка выбирается из дискретного списка камеры.

Если секций нет в файле, обе функции выключены. Неверное значение выводится при запуске с префиксом камеры (`asi.`, `japan.`, `sptt.`, `infra.`), и функция выключается.

```json
"preflight": { "enabled": true, "sun_start_angle": -6.0, "target_mean": 20000.0 },
"overexposure": { "enabled": true, "threshold": 55000.0, "max_splits": 4 }
```

## Предварительная стадия (preflight)

Обычно между «ещё светло» и `sun_max_angle` не снимается ничего: слотовые экспозиции в сумерках дают насыщение. Предварительная стадия занимает этот промежуток.

Она стартует по первой, более высокой уставке угла Солнца и идёт по основному расписанию: те же слоты, дельты, фильтры, биннинг, усиление и фаза цикла. Экспозицию каждого слота она подбирает сама, удерживая заданную среднюю интенсивность кадра. Когда Солнце доходит до `sun_max_angle`, автоматика выключается и идёт обычный цикл.

Порядок вечера: предварительные тёмные кадры (заканчиваются к первой уставке) → затвор открывается → предварительная стадия → основной цикл. На рассвете сессия завершается как обычно, при подъёме Солнца выше `sun_max_angle`. Утром стадия не повторяется.

| Ключ | По умолчанию | Описание |
|---|---|---|
| `enabled` | `false` | включает стадию |
| `sun_start_angle` | `-6.0` | первая уставка, градусы; должна быть **выше** `sun_max_angle` |
| `target_mean` | `20000.0` | удерживаемое среднее по кадру, АЦП 0–65535 |
| `tolerance` | `0.15` | мёртвая зона в долях цели |
| `min_exposure` | `0.05` | нижний предел экспозиции, с |
| `max_exposure` | `null` | верхний предел; `null` — не длиннее экспозиции слота |
| `max_step` | `4.0` | наибольший множитель изменения экспозиции за одно измерение |
| `bias` | `0.0` | пьедестал, АЦП; запасное значение, см. [Пьедестал](#пьедестал) |
| `binning` | `null` | общий биннинг стадии; `null` — у каждого слота свой. ASI: 1–4, Japan: 1–8 |

Экспозиция ведётся по каждому слоту отдельно: разные фильтры смотрят на небо разной яркости. Первый заход начинается с `min_exposure` и растёт, чтобы не получить пересвеченный кадр на старте.

Кадры стадии получают `OBSMODE = sun_cycle_auto` и суффикс `_pf` в имени файла.

### Предварительная стадия у SPTT

У SPTT нет слотов: стадия работает на тех же `capture_seconds` и только в `mode: "sun"`. В режиме `always` включённая стадия выключается с сообщением.

- Окно съёмки открывается на `sun_start_angle`, а не на `sun_max_angle`. До `sun_max_angle` экспозиция подбирается автоматически, затем снимается заданная `exposure`.
- Стадия только вечерняя. После `sun_max_angle` окно закрывается при подъёме Солнца выше `sun_max_angle`, утренние сумерки до `sun_start_angle` не снимаются. Если программа запущена утром между двумя углами, она ждёт вечера.
- Каждую ночь подбор начинается заново с `min_exposure`.
- Потолок экспозиции — заданная `exposure` и промежуток до следующего тика за вычетом считывания.
- Кадры стадии получают `OBSMODE = sun_auto` и имя `YYYYmmddTHHMMSS_pf.fit`.
- Тёмных кадров у SPTT нет, пьедестал берётся из `preflight.bias`.

## Защита от пересветки (overexposure)

Если средняя интенсивность на слоте превысила порог, в следующий заход на этот слот один кадр экспозиции `E` разбивается на `N` более коротких подкадров подряд.

Бюджет слота — один кадр плюс одно сохранение, `E + dt`. В него должны уложиться `N` подкадров с `N` сохранениями:

```
N · (e + dt) = E + dt − margin        e = (E + dt − margin) / N − dt
```

Подкадр получается чуть короче `E / N`. Для расписания с `E` = 55 с, `readout` = 5 с и слотами через 60 с это 25 с при `N` = 2, 15 с при `N` = 3 и 10 с при `N` = 4.

Если разбиения мало, `N` растёт по одному за заход, пока интенсивность не опустится ниже порога или `N` не упрётся в предел. Предела два: `max_splits` и арифметический:

```
N ≤ (E + dt − margin) / (e_min + dt)
```

Здесь `e_min` не меньше `min_frame_gap` за вычетом мёртвого времени.

Обратно слот возвращается по прогнозу: измеренная интенсивность пересчитывается на более длинную экспозицию, и когда прогноз для целого кадра ниже `threshold · release`, слот снова снимает один кадр. Промежуточные шаги вниз тоже разрешены.

| Ключ | По умолчанию | Описание |
|---|---|---|
| `enabled` | `false` | включает защиту |
| `threshold` | `55000.0` | среднее по кадру, выше которого слот дробится, АЦП 0–65535 |
| `release` | `0.85` | гистерезис возврата |
| `max_splits` | `4` | наибольшее число подкадров, не меньше 2 |
| `min_exposure` | `0.05` | наименьшая экспозиция подкадра, с |
| `margin` | `0.5` | запас внутри бюджета слота, с |
| `min_frame_gap` | `1.0` | наименьший интервал между подкадрами, с; не ниже 1 с |
| `bias` | `0.0` | пьедестал, АЦП; запасное значение |

`min_frame_gap` не опускается ниже секунды: имя файла имеет разрешение в одну секунду. Если мёртвое время съедает весь бюджет, разбиение невозможно: слот снимается целым кадром, и об этом один раз пишется в лог.

### Камеры с тиками: SPTT и Infra

У этих камер один «слот» — кадр на секунде из `capture_seconds`, и бюджет тот же: `E + dt`, где `E` — заданная экспозиция.

| | `dt` | Экспозиция между тиками |
|---|---|---|
| SPTT | оценка захвата камеры минус экспозиция: передача по USB, в непрерывном режиме ещё и период | остаётся экспозиция подкадра или стадии: в непрерывном режиме каждая смена стоит кадра, поэтому бюджет стадии оставляет на него место |
| Infra | измеренный интервал между кадрами потока минус экспозиция; пока поток не снял два кадра подряд, защита не работает | остаётся экспозиция подкадра: смена стоит потоку кадр-два, поэтому меняется только вместе с `N` |

`focus_app.py`, статус и монитор показывают заданную экспозицию, хотя живой поток между тиками идёт на экспозиции подкадра. Её изменение на лету начинает расчёт заново. Во вкладке SPTT в `gui_app.py` поле экспозиции на время измерения заблокировано, меняйте её через `focus_app.py`.

Подкадры должны отстоять друг от друга на `min_frame_gap`, поэтому короткие экспозиции не делятся. При 0,88 с и `dt` около 0,5 с бюджет меньше двух секунд, и SPTT снимает целый кадр с однократной строкой в логе. Infra с экспозицией в миллисекунды не делится вовсе. Разбиение полезно при экспозициях от нескольких секунд, например SPTT с `capture_seconds: [0]` и экспозицией 30–55 с.

Подкадры пишутся отдельными файлами под своими секундами. У Infra карты `SPLITNUM` и `SPLITIDX` есть только в FITS: у TIFF и PNG шапки нет.

## Пьедестал

Среднее по кадру — это `bias + сигнал`, и с экспозицией растёт только сигнал. Обе функции считают по сигналу над пьедесталом, иначе пересчёт экспозиции ошибается в опасную сторону.

Пьедестал берётся из предварительных тёмных кадров. Ключ `bias` нужен, только когда их нет: `dark_frames = 0` или поздний старт.

У SPTT и Infra нет затвора и тёмных кадров, поэтому пьедестал всегда берётся из `bias`. Его стоит задать по закрытому объективу: при `0` прогноз для более длинной экспозиции получается заниженным.

## Карты FITS

| Карта | Значение |
|---|---|
| `OBSMODE` | ASI и Japan: режим или `sun_cycle_auto`; SPTT: `always`, `sun` или `sun_auto` |
| `SKYMEAN` | измеренная средняя интенсивность, АЦП; на каждом кадре |
| `SPLITNUM` | на сколько частей поделён слот |
| `SPLITIDX` | номер подкадра, с единицы |

Имя файла всегда содержит экспозицию, с которой кадр снят на самом деле.
