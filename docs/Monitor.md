# Монитор

`monitor_app.py` показывает каждую камеру плиткой: что это, на какой машине работает, чем занята и что пошло не так.

```bash
python monitor_app.py                         # найти камеры в локальной сети
python monitor_app.py --host 192.168.1.5      # добавить камеру, которой нет в обнаружении
python monitor_app.py --interval 5            # период опроса статусов, секунд
python monitor_app.py --via 192.168.1.5:8765  # и всё, что знает эта камера
python monitor_app.py --config /path/to.json  # другой файл конфигурации
```

`--host` можно указывать несколько раз.

## Источники

**Локальная сеть — основной.** Камеры находятся [UDP-обнаружением](Discovery-And-Gateway.md), а плитка заполняется из `GET /api/status` самой камеры. Настраивать нечего. Кнопка **Search LAN** повторяет поиск, флажок **Keep searching** делает это раз в 20 секунд, чтобы запущенная позже камера появилась сама.

**Через шлюз.** Панель внизу окна, свёрнутая по умолчанию, спрашивает у названной камеры `GET /api/nodes`, и её соседи становятся такими же плитками. Это нужно, когда широковещание не проходит через коммутатор, или с машины, у которой есть маршрут ровно к одной камере. Камера, видимая обоими путями, показывается напрямую.

## Плитка

На плитке: статус, тип камеры, имя машины и адрес, затем показания, зависящие от типа: фаза и режим расписания, экспозиция и биннинг, колесо фильтров и затвор, температура с уставкой, число кадров, время последнего кадра, обратный отсчёт до слота, свободное место, число ошибок. Отдельной строкой отмечаются режим настройки и идущая фокусировка.

| Кнопка | Что делает |
|---|---|
| **Frames…** | запускает `viewer_app.py` с адресом камеры |
| **Focus…** | запускает `focus_app.py` с адресом камеры |
| **Details** | показывает статус целиком |

У камеры, найденной через шлюз, кнопки тоже работают: программе передаётся `--via`.

## Статусы

| Статус | Цвет | Описание |
|---|---|---|
| `RUNNING` | зелёный | камера снимает |
| `WAITING` | оранжевый | ожидание расписания |
| `ERROR` | красный | ошибка при съёмке |
| `STOPPED` | серый | остановлена |
| `OFFLINE` | оранжевый | камера не отвечает, причина написана на плитке |
| `SETUP` | оранжевый | [режим настройки](Setup-Mode.md) |
| `STALE` | оранжевый | нет обновлений более 30 секунд |

Камера, пропавшая из ответов, не исчезает: плитка остаётся с пометкой `OFFLINE`. Для этого нужно два пропуска подряд, один потерянный UDP-ответ ничего не меняет.

## Вкладка Monitor в gui_app.py

Таблица со статусами камер этой машины осталась вкладкой **Monitor** в `gui_app.py`. Записи процессов, которых больше нет в системе, помечаются как `STOPPED` и `(dead)`.
