# Камера SPTT

Семейство камер CSDU по USB. Кадры пишутся в FITS на заданных секундах каждой минуты, между ними камера работает свободным ходом и отдаёт живой поток.

```bash
python main.py --type sptt
```

## Модели

Драйвер определяет модель по USB ID:

| Модель | USB ID до и после прошивки | Сенсор | Кадр 1×1 |
|---|---|---|---|
| CSDU-429, CSDU-423 | `DCDC:F429` → `DCDC:E429` | ICX429, чересстрочный, ч/б | 744×576 |
| CSDU-285C | `DCDC:D285` → `DCDC:C285` | ICX285AQ, прогрессивный, Bayer (RGGB) | 1392×1032 |

Ключ `INSTRUME` в FITS содержит имя модели. «CSDU Gray», «CSDU Color» и «Um_2» из дистрибутива производителя — это программы, а не отдельные камеры.

## Подключение

Кроме доступа к USB, root не нужен: порт LAN-сервера выше 1024, логи и статус пишутся в `~/.every_camera/`. Правило udev лежит в репозитории:

```bash
sudo cp systemd/99-every-camera-sptt.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger
# затем отключить и снова подключить камеру
```

`sudo systemd/install.sh sptt` ставит это правило сам. Оно покрывает оба USB ID каждой модели. Vendor ID у камер — `dcdc`. Без правила программа сообщает, какое правило поставить.

Проверка: права устройства должны быть `crw-rw-rw-`.

```bash
lsusb -d dcdc:                          # Bus 001 Device 007: ID dcdc:e429
ls -l /dev/bus/usb/001/007
python3 main.py --type sptt --preview   # без sudo
```

Служба по умолчанию запускается от root. Чтобы она работала от имени оператора:

```bash
sudo systemctl edit every-camera@sptt
#   [Service]
#   User=alex
sudo systemctl restart every-camera@sptt
```

Каталог `sptt.output_dir` должен быть доступен этому пользователю на запись.

На Linux камера загружает прошивку при запуске. Вручную то же делает загрузчик:

```bash
python -m cameras.sptt_load_firmware --list         # список камер
python -m cameras.sptt_load_firmware --port 1-2.3   # загрузить в камеру на этом порту
```

## Параметры

| Ключ | По умолчанию | Описание |
|---|---|---|
| `instance_name` | `""` | имя экземпляра; пусто — `SPTT_<узел>` |
| `output_dir` | `""` | каталог для FITS |
| `capture_seconds` | `[0, 30]` | секунды каждой минуты для плановых снимков |
| `exposure` | `0.88` | экспозиция, с |
| `period_us` | `null` | период кадра, мкс; `null` — вычисляется по экспозиции |
| `trigmode` | `null` | режим запуска, см. ниже |
| `gain` | `100` | усиление, 0–1023 |
| `binning` | `0` | `0` = 1×1, `1` = 2×2, `3` = 4×4 |
| `encoding` | `1` | разрядность оцифровки: `0` = 8 бит, `1` = 12 бит |
| `target_temp` | `null` | целевая температура ПЗС, °C; `null` — не задано |
| `firmware_dir` | `""` | каталог прошивки; пусто — `firmware/` в корне программы |
| `usb_port` | `""` | физический USB-порт, например `1-2.3`; пусто — единственная камера на машине |
| `debayer` | `false` | только CSDU-285C: `true` — RGB-куб 3×H×W, `false` — сырая мозаика с `BAYERPAT` |
| `bayer_pattern` | `RGGB` | только CSDU-285C: также `GRBG`, `GBRG`, `BGGR` |
| `r_offset`, `g_offset` | `null` | смещения каналов цветной камеры; `null` — не отправлять, у вендора `0` и `30` |

Ключи `debayer`, `bayer_pattern`, `r_offset`, `g_offset` необязательны: значения по умолчанию заданы в программе, в `config.json` их можно не писать.

Значения `trigmode`: `null` или `0` — непрерывный, `1` — внешний, `2` — программный, `3` — bulb, `5` — внешний одиночный, `7` — bulb одиночный. Вне непрерывного режима период не влияет на накопление и передаётся камере как есть.

При любом `encoding` значения в кадре приведены к общей [шкале 0–65535](Intensity-Scale.md).

**Файлы прошивки.** Для CSDU-429/423 это `fx2_firmware.bin` и `fpga_bitstream.bin` или вендорский `c2-429.spt`. Для CSDU-285C — `csdu285.spt` (вендорский `CSDU285.SPT`). Относительный путь в `firmware_dir` отсчитывается от корня программы. Если файлов нет, камера не поднимется, а в журнале будет указан путь поиска.

**Несколько камер.** Если их больше одной, `usb_port` обязателен: см. [Службы systemd](Systemd.md#несколько-камер-sptt-на-одном-пк).

Кадры называются по местному времени и никогда не перезаписываются: повторное имя (перевод часов назад) получает суффикс `_2`, `_3` и так далее.

## Цветная камера

При фокусировке кадр CSDU-285C показывается в цвете: в режиме `--setup`, в `focus_app` и в живом просмотре по сети. Дебайер использует тот же `bayer_pattern`. Если красное и синее поменялись местами, настройте этот ключ.

Резкость, статистика и гистограмма считаются по среднему трёх цветов, поэтому мозаика не выдаёт себя за мелкие детали. Дебайер полного кадра занимает около 0,13 с.

## Съёмка CSDU-285C

CSDU-285C снимает по одному кадру с программным запуском, как демо-программа производителя: очистка FIFO, запуск, ожидание данных, чтение. В FITS это `TRIGMODE = 2`. Значение `null` или `0` в `sptt.trigmode` включает этот режим, внешний запуск `1`, `3`, `5`, `7` работает как задано.

Так кадр начинается в момент запроса, а его накопление всегда равно экспозиции. Медленный USB, например на Raspberry Pi, удлиняет передачу, но не портит кадр. Разделы про период и живой поток ниже относятся к непрерывному режиму CSDU-429/423, `period_us` на CSDU-285C не влияет.

**Биннинга у CSDU-285C нет.** Прошивка принимает команду, но кадр и сигнал не меняются, поэтому `binning` сбрасывается в `0` с предупреждением в журнале. Кадр всегда полный и цветной.

Размер кадра задаёт ROI. Камера помнит ROI до отключения питания, поэтому драйвер при настройке всегда возвращает полный кадр 1392×1032.

Если камера перестала отдавать кадр, драйвер снимает его ещё раз. Повторный отказ попадает в журнал с числом полученных байт: `Camera sent N of M frame bytes`.

## Экспозиция и период кадра

Экспозиция и период — два независимых регистра. В непрерывном режиме период задаёт интервал кадра, поэтому **период короче экспозиции обрезает накопление**: кадры получаются тёмными, и ни камера, ни программа об этом не сообщают.

Поэтому период выводится из экспозиции: экспозиция плюс 75 000 мкс на считывание и передачу, но не меньше аппаратного минимума, который сообщает камера. Он пересчитывается при каждом изменении экспозиции, в том числе из `focus_app.py` и GUI. Заданный вручную `period_us` короче экспозиции поднимается до безопасного значения с предупреждением в журнале.

После установки параметров программа сверяет фактические экспозицию и период с запрошенными. Расхождение считается отказом:

- на старте камера не запускается;
- при смене на лету ошибка возвращается в `focus_app` или в ответ по сети, а расписание продолжает работать на последнем исправном значении.

При длинной экспозиции частота предпросмотра падает: при 0,88 с это примерно один кадр в секунду.

## Шапка FITS

| Ключ | Значение |
|---|---|
| `DATE-OBS` | момент, когда камере разрешено начать накопление |
| `EXPTIME` | экспозиция, которую сообщила камера; используйте её в фотометрии |
| `EXPREQ` | запрошенная экспозиция; при исправной работе совпадает с `EXPTIME` |
| `PERIOD` | фактический период кадра, мкс |
| `MINPERD` | минимальный период при текущем биннинге и ROI |
| `TRIGMODE` | режим запуска |
| `FRAMELAG` | секунды от разрешения на накопление до получения кадра |
| `READTIME` | сколько длилась передача кадра по USB |

Плановый снимок в `:00` и `:30` начинает собственный кадр, а не забирает кадр, пролежавший в FIFO.

## Мёртвое время между кадрами

Следующее накопление начинается, когда программа дочитала кадр и переинициализировала FIFO. Всё, что происходит между этими событиями, становится мёртвым временем. Чтобы уменьшить его разброс:

- готовность кадра опрашивается с шагом 5 мс;
- состояние камеры в цикле измерений опрашивается с частотой публикации статуса;
- кадр читается запросами по 64 КиБ.

Разброс виден в архиве по ключу `FRAMELAG`. Если `READTIME` больше `PERIOD`, камера выдаёт кадры быстрее, чем их успевают забирать, и в журнале появляется предупреждение, не чаще раза в минуту.

## Живой поток

В непрерывном режиме камера начинает следующий кадр через период после предыдущего, прочитан он или нет. Кадр CSDU-285C (2,15 МБ) может идти по USB дольше периода, и тогда байты теряются на стыке кадров: изображение сдвигается вбок или превращается в шум. Поэтому:

- если сбор кадра с обработкой занял больше периода, драйвер удлиняет период до этого времени с запасом 25 % + 50 мс и перезапускает съёмку. В журнале появляется `Frame period raised to … s`, новый период виден в статусе и в `PERIOD`. Заданный вручную `period_us` и режимы запуска не меняются, выводится только предупреждение;
- при переполнении FIFO (`FIFO full`) съёмка перезапускается;
- после чтения FIFO сбрасывается, только если он пуст.

Удлинённый период означает более редкие кадры, но не более короткую выдержку.
