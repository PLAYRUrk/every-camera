# Доступ извне (Cloudflare Tunnel)

Камеры доступны не только из локальной сети. Вместе с программой поднимается
[quick tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/do-more-with-tunnels/trycloudflare/)
Cloudflare: случайный адрес вида `https://<слова>.trycloudflare.com`, который ведёт к
HTTP-серверу кадров этой камеры. Аккаунт Cloudflare, открытые входящие порты и ввод
данных не нужны: узел сам устанавливает исходящее соединение.

Адрес меняется при каждом запуске камеры. Его присылает письмом `sentinel.py` сразу после
запуска и затем раз в `mail_minutes`. Адрес появляется в статусе и в письме только после
того, как Cloudflare зарегистрировал соединение (`Registered tunnel connection` в выводе
`cloudflared`): раньше он отвечал бы ошибкой 530.

## Отказ туннеля не мешает съёмке

- туннель работает в отдельном daemon-потоке и в отдельном процессе `cloudflared`;
- нет `cloudflared`, сети или GitHub — в логе одно предупреждение, съёмка идёт, а поиск
  и скачивание повторяются с той же растущей паузой: сеть может появиться позже камеры;
- `cloudflared` упал или потерял связь — перезапуск через 30 с, затем пауза растёт до
  10 минут; новый адрес придёт новым письмом;
- сообщения туннеля пишутся с уровнем WARNING, поэтому сами по себе не вызывают писем об
  ошибках;
- строки `ERR` из вывода `cloudflared` попадают в лог камеры (не чаще раза в минуту, с
  числом пропущенных), а при выходе `cloudflared` в лог пишутся код выхода и последние
  20 строк его вывода;
- если процесс камеры падает, `cloudflared` завершается вместе с ним (Linux:
  `PR_SET_PDEATHSIG`, Windows: Job Object).

## Что доступно через туннель

Туннель ведёт не на порт локальной сети, а на отдельный слушатель `127.0.0.1` со
случайным портом.

| Что | Без токена | С токеном |
|---|---|---|
| веб-страница, архив, миниатюры, живой поток, статус | да | да |
| соседние камеры через [шлюз](Discovery-And-Gateway.md#шлюз), только чтение | да | да |
| `POST /api/params` — изменение параметров | 403 | да |
| `POST /api/focus` — режим фокусировки | 403 | да |
| POST к соседним камерам через шлюз | 403 | да |

Токен создаётся заново при каждом запуске и приходит в том же письме. Он передаётся
заголовком `X-Everycam-Token` или параметром `?token=`. Через `/api/status` и шлюз
токен не выдаётся: он есть только в статус-файле на самой машине.

Доступ из локальной сети не меняется: там токен не нужен.

> Адрес с токеном даёт право менять параметры съёмки. Пересылайте письмо только тем,
> кому это можно. Адрес без токена тоже стоит держать при себе: по нему видны кадры.

## Письмо с адресами

Одно письмо на машину, по строке на каждую камеру:

```
Узел TORY (tory-asi), 2026-11-08T18:00:30

ASI_ASI (asi)
  браузер:      https://quiet-owl-test.trycloudflare.com/
  с токеном:    https://quiet-owl-test.trycloudflare.com/?token=…
  токен:        …
```

- Сразу после запуска: письмо уходит, когда адреса всех камер машины не менялись 30 с,
  так что камеры, запущенные вместе, приходят одним письмом.
- Появился новый адрес — новое письмо. Камера остановилась или её туннель
  перезапускается — письма нет, оно придёт с новым адресом.
- Раз в `mail_minutes` — повтор, даже если ничего не менялось.
- Перезапуск сторожа без смены адресов повтора не вызывает.
- Адресаты — `server.tunnel.to`, а если список пуст, то `alerts.to`.
- Письма считаются в общий суточный лимит `alerts.max_per_day`.

Адрес туннеля также добавляется в регулярную сводку
`alerts.status_mail_minutes` (без токена).

Отправить письмо с адресами сейчас:

```bash
python sentinel.py --tunnel-mail
```

## Подключение viewer_app и focus_app

В поле адреса камеры вставьте адрес из письма. Для просмотра достаточно адреса, для
фокусировки нужен адрес с токеном:

```bash
python viewer_app.py --host https://quiet-owl-test.trycloudflare.com
python focus_app.py --host "https://quiet-owl-test.trycloudflare.com/?token=…"
```

Соседняя камера той же станции через туннель:
`--via https://quiet-owl-test.trycloudflare.com --host 192.168.1.20 --port 8765`.

Адреса туннеля не запоминаются в списке недавних: при следующем запуске камеры они
недействительны.

## Параметры

Секция `server.tunnel` в `config.json`:

| Ключ | По умолчанию | Описание |
|---|---|---|
| `enabled` | `true` | поднимать туннель вместе с программой |
| `to` | `[]` | кому слать адрес; пусто — `alerts.to` |
| `mail_minutes` | `180` | повтор письма; `0` — только при смене адреса |
| `cloudflared` | `""` | путь к `cloudflared`; пусто — искать автоматически |
| `auto_download` | `true` | скачать `cloudflared`, если не найден |
| `protocol` | `"http2"` | протокол связи с Cloudflare: `http2` — TCP 443, `quic` — UDP 7844, `auto` — сначала QUIC |

Туннель работает только при включённом сервере кадров (`server.enabled`). Настройки
есть в мастере настройки: вкладка **LAN Server**, группа
**Access from outside (Cloudflare)**.

## Откуда берётся cloudflared

По порядку:

1. путь из `server.tunnel.cloudflared`;
2. `cloudflared` в `PATH`;
3. `~/.every_camera/bin/cloudflared` (на Windows `cloudflared.exe`);
4. если `auto_download` включён — скачивание официальной сборки из
   `github.com/cloudflare/cloudflared/releases/latest` в `~/.every_camera/bin`.

Скачивается один раз на машину: если камер несколько, остальные ждут. Сборки есть для
Linux (amd64, arm64, 386, arm) и Windows (amd64, 386). На машине без доступа к GitHub
положите файл в `~/.every_camera/bin` вручную. Скачанное, что не похоже на исполняемый
файл (например, страница входа в сеть), не сохраняется.

`cloudflared` запускается с `--config ~/.every_camera/bin/quick-tunnel.yml`: свой
`config.yml` в `~/.cloudflared` или `/etc/cloudflared` (например, от именованного туннеля)
на quick tunnel не влияет.

## Если адрес не открывается

Причину сначала смотреть в логе камеры: строки `Tunnel:` и `Frame server (tunnel): 500`.

| Код | Что значит | Что делать |
|---|---|---|
| 530 (Cloudflare 1033) | у адреса нет живого соединения с `cloudflared` | адрес устарел (камера перезапускалась — нужен адрес из последнего письма) или `cloudflared` не может связаться с Cloudflare: в логе `ERR` с причиной |
| 502 | `cloudflared` работает, но не достучался до сервера кадров | камера останавливается или её сервер кадров не запустился |
| 503 от Cloudflare | `cloudflared` не нашёл, куда отправить запрос | обычно чужой `config.yml`; с текущей версией не должно повторяться |
| 503 `Too many live streams` | открыто больше 4 живых потоков | закрыть лишние окна просмотра |
| 500 | ошибка в обработчике сервера кадров | в логе камеры `Frame server (tunnel): 500 on …` с traceback |
| 429 в логе | Cloudflare ограничил создание quick tunnel с этого адреса | ждать: перезапуск идёт с растущей паузой |

Первые секунды после письма адрес может не открываться, пока не разошлась DNS-запись:
обновите страницу.

## Ограничения quick tunnel

- адрес случайный и меняется при каждом перезапуске;
- Cloudflare не даёт гарантий доступности для quick tunnel: это средство для доступа
  наблюдателя, а не для передачи данных;
- живой поток MJPEG через туннель может идти с задержкой.
