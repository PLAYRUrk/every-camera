# Обнаружение и шлюз

Камеры находят друг друга сами, а одна доступная камера открывает доступ ко всем остальным.

## Обнаружение камер

```bash
python discovery.py --timeout 2
python discovery.py --port 45455
```

Команда рассылает запрос по UDP и печатает ответившие камеры:

```
Tory-1               ASI_42               asi      http://192.168.1.42:8801
Sura-2               Infra_17             infra    http://192.168.1.17:8765
```

Колонки: [имя узла](Node-Name.md), имя экземпляра, тип камеры, адрес. Тот же механизм использует кнопка **Search LAN**.

Запрос идёт в multicast-группу `239.255.42.99` и широковещательно: см. [Несколько экземпляров](Multi-Instance.md#обнаружение).

Каждая камера также раз в минуту объявляет о себе в ту же multicast-группу. Поэтому камера, запущенная позже, появляется сама, и её адрес попадает в реестр.

## Реестр узлов

Всё увиденное записывается в `~/.every_camera/peers/`, по файлу на узел:

```
~/.every_camera/peers/192.168.2.36_8765.json
{"host": "192.168.2.36", "http_port": 8765, "node_name": "TORY",
 "instance_name": "ASI_ASI", "camera_type": "asi", "last_seen": 1787817250.4}
```

При следующем поиске эти адреса опрашиваются ещё и адресно. Там, где широковещание режется коммутатором или границей VLAN, камеру достаточно увидеть один раз.

Записи старше месяца забываются. Каталог можно удалить без последствий: потеряется один раунд поиска.

Каталог общий для всех камер машины, поэтому файлы отдельные: один общий файл терял бы записи при одновременной записи из нескольких процессов.

## Шлюз

Любая камера умеет сходить к соседней вместо вас:

```bash
curl http://192.168.2.36:8765/api/nodes                       # кого она знает
curl http://192.168.2.36:8765/api/node/10.0.0.5:8765/api/status
```

Достаточно дотянуться до одной камеры. Программы наблюдателя принимают ключ `--via`:

```bash
python monitor_app.py --via 192.168.2.36:8765
python viewer_app.py  --host 10.0.0.5 --via 192.168.2.36:8765
python focus_app.py   --host 10.0.0.5 --via 192.168.2.36:8765
```

Проксируется целый HTTP-запрос, поэтому через шлюз работает всё: архив, `/api/live.mjpg`, `/api/params`, `/api/focus`.

Ограничения:

- переслать запрос можно только к узлу, который эта камера действительно видела, иначе она стала бы открытым прокси;
- пересылка пересылки запрещена: счётчик переходов в заголовке не даёт двум камерам гонять запрос между собой.

> Доступ к серверу кадров не аутентифицируется, он рассчитан на доверенный сегмент. Шлюз ходит только туда, куда и так дотянулась бы любая программа на той же машине.
